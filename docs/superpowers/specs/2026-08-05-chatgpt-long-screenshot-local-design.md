# ChatGPT 分享链接本地长截图设计

## Context

用户在 iPhone 上可以获得 ChatGPT 公开分享链接，却无法方便地截取完整聊天长图。第一阶段交付目标是：在本地构建一个可完整运行、验证和打包迁移的应用；第二阶段将同一渲染核心接入 GitHub CI 和 Cloudflare。

第一版仅支持形如 `https://chatgpt.com/s/t_<32位小写十六进制>` 的公开分享链接，以及“原站还原”样式。未来需要支持 Gemini、Claude、豆包等平台和苹果/阅读等自定义风格，因此核心仍采用“平台适配器 × 渲染策略”边界，但不提前实现未上线的平台或主题。

## 产品范围

- 主要入口是手机网页，也可在桌面浏览器使用。
- 一条 `pnpm dev` 命令启动静态网页和截图 API。
- 本地默认只监听 `127.0.0.1`；显式设置 `HOST=0.0.0.0` 后，同一可信局域网内的 iPhone 可访问。
- 第一版只接受公开的 ChatGPT 分享链接，不支持私有聊天、登录 Cookie 或任意网页截图。
- 只截取保留 ChatGPT 原生视觉的对话正文；隐藏导航、登录/分享按钮、输入框、页脚与浮动控件。
- 尽量返回单张 PNG；单图受尺寸或内存限制时，按正文顺序返回连续 PNG 分图。
- 不建立账号、数据库、队列、对象存储或永久历史。
- 第一阶段只完成本地运行和验证；Cloudflare 部署属于后续独立阶段。

## 架构

```text
iPhone / 桌面浏览器
        ↓ 同源 HTTP
本地 Node 服务
  ├─ 静态网页
  └─ POST /api/render
        ↓
BrowserSession 接口
        ↓
Playwright Chromium
        ↓
ChatGptAdapter + NativeRenderStrategy
        ↓
单张 PNG / multipart 有序分图
```

### 本地服务

Node 服务负责静态资源和 `/api/render`，避免本地双进程、跨域与多个端口。开发模式可以让 Vite 提供前端构建能力，但对用户只暴露一个启动命令和一个访问地址。生产式本地验证使用构建后的静态资源和同一个 Node 服务。

### 浏览器运行时

`BrowserSession` 定义页面打开、网络策略、等待、DOM 执行与截图接口。第一版实现 `PlaywrightBrowserSession`，启动本机安装的 Chromium。未来接 Cloudflare Browser Rendering 时新增一个运行时实现，不修改 URL 校验、平台适配器、截图规划、API 或前端。

### 平台适配器

`PlatformAdapter` 负责平台特有行为：

- 校验并规范化分享链接；
- 限制目标页面及子资源请求；
- 判断内容何时加载完成；
- 定位消息和共同正文根节点；
- 隐藏非对话 UI，并提供消息边界。

第一版仅注册 `ChatGptAdapter`。未来平台通过显式注册新增，不提供通用 URL 回退。

### 渲染策略

`NativeRenderStrategy` 保留目标站点已渲染的消息 DOM 和样式，只做正文隔离与截图。未来苹果/阅读主题使用结构化内容提取和自有模板重绘，但不属于第一版。

## 数据流

1. 用户粘贴公开 ChatGPT 分享链接并提交。
2. 前端做格式提示，服务端执行最终严格校验。
3. 服务端通过 Playwright 打开无登录态 Chromium 页面，并在导航前安装静态网络白名单。
4. 适配器等待消息、字体和图片，进行有界滚动以触发懒加载，并等待高度稳定。
5. 适配器隐藏无关 UI，测量正文矩形和消息纵向边界。
6. 截图器在安全范围内生成单张 PNG；若超过高度/字节阈值或全图截图失败，则按消息边界优先分图。
7. 前端以内存 Blob URL 预览并允许用户主动保存；替换结果或关闭页面时释放 URL。

## 本地使用与打包

- `pnpm install` 安装依赖。
- `pnpm exec playwright install chromium` 安装本地 Chromium。
- `pnpm dev` 启动默认本机服务。
- `HOST=0.0.0.0 pnpm dev` 允许同一可信局域网中的 iPhone 访问，终端显示实际 URL 和安全提示。
- `pnpm build && pnpm start` 验证打包后的运行方式。
- 提供源码打包命令，排除 `.git`、`node_modules`、构建缓存、截图结果和本地日志；锁文件必须包含在包中。
- README 说明在新电脑解压、安装依赖、安装 Chromium、启动服务以及未来部署需要替换浏览器运行时的边界。

## 安全与隐私

- 仅允许 HTTPS、精确主机 `chatgpt.com` 和第一版确认的分享路径；拒绝凭据、非标准端口、查询参数、片段、IP 和编码绕过。
- 浏览器请求按静态平台白名单放行，阻断私网、回环、链路本地、云元数据地址和任意第三方跳转。
- 默认监听 `127.0.0.1`；局域网模式必须显式开启，并在文档中要求仅用于可信网络。
- 轻量限制每个源 IP 的请求频率、每个进程的总并发及单 IP 并发；不排队，不无限重试。
- 不记录完整 URL、分享 ID、对话正文、HTML、Cookie、浏览器 console 或图片字节。
- 响应设置 `Cache-Control: no-store`；不把 URL 放入查询参数、浏览器存储或下载文件名。
- 浏览器上下文每次任务隔离且任务后关闭，不复用登录状态。

## 错误处理

前端区分并显示不泄密的中文错误：

- 链接格式不受支持；
- 分享链接失效或不是公开页面；
- ChatGPT 页面结构变化，无法定位正文；
- 页面或资源加载超时；
- 浏览器启动失败；
- 请求过快或并发超限；
- 对话过大，分图后仍超出安全限制。

原始 Playwright 错误不直接返回给前端，也不附带目标 URL。

## 验证

- 单元测试：URL 绕过、平台注册、网络策略、错误脱敏、截图规划、multipart 编解码、UI 状态机。
- 集成测试：用 fake browser 覆盖单图、分图、超时、正文缺失、浏览器失败与限流。
- 本地真实 smoke：用批准的公开链接覆盖短文本、Markdown/代码块、图片、长对话和失效链接；只记录尺寸、耗时、模式和字节数。
- 浏览器 E2E：Playwright 驱动本地网页完成输入、生成、预览、下载及错误恢复。
- iPhone 真机：同一可信 Wi-Fi 访问局域网地址，验证输入不缩放、安全区、单图保存、分图逐张保存和内存稳定性。
- 打包验收：在干净目录解压源码包，按 README 完成安装、Chromium 下载、构建和启动。

## 第一阶段非目标

- 不在本地 MVP 中实现 Cloudflare Browser Run 适配器；云端运行时作为后续阶段新增。
- 不实现 Gemini、Claude、豆包适配器。
- 不实现苹果风格、阅读风格或结构化抓取。
- 不支持私有聊天、用户登录、永久存储、历史记录或公开多租户服务。
